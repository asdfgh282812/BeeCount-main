# 股票與報表一致性稽核與修正

日期:2026-10-03
Cloud 端對應:`BeeCount-Cloud/docs/STOCK_HOLDINGS_SD.md`(Web 首頁/報表請採用本文件最後一節的口徑)。

## 需求

> 原本 App 端的報表,我希望可以確保在呈現的時候,不會有任何衝突(例如:因為股票交易是不納入
> 總額,所以金額會少,報表要能得知相關資訊等等)。

## 先釐清:現有口徑(查證結果,以此為準)

| 項目 | 現有算法 | 出處 |
|---|---|---|
| 收入/支出統計 | 只算 `type = income/expense`(含退款沖銷),**轉帳一律不計**,連同它的 `feeAmount`/`discountAmount` | `local_statistics_repository.dart::_rangeTotals`、`report_aggregator.dart`;Cloud `workspace.py::_stat_legs`(轉帳 `flow=None`) |
| 帳戶餘額 | `initial + income − expense − (轉出 amount + feeAmount) + (轉入 (toAmount ?? amount) − discountAmount) + adjustment` | `local_account_repository.dart::_transferOutEffect/_transferInEffect`;Cloud `recurring_materializer.compute_account_balance` |
| 淨資產 | 只加 `includeInTotal = true` 的帳戶餘額;新建投資理財帳戶預設 `false` | `getNetWorthBreakdown*` |
| 股票買進 | 轉帳 交割戶→投資戶,`amount`=股數×價(取整),`feeAmount`=手續費 | `stock_trade_tx_mapper.dart` |
| 股票賣出 | 轉帳 投資戶→交割戶,`amount`=股數×價,`discountAmount`=手續費+證交稅 | 同上 |
| 股利 | `income`(分類「股利」);現金股利入交割戶(實收),再投入入投資戶本身(成本) | `createStockTrade` |

兩個推論(也是這次的設計依據):

1. **手續費/證交稅沒有進任何收支報表**(App 與 Cloud 一致),但**會讓帳戶餘額減少**。
   所以「全部帳戶餘額變化 = 收入 − 支出 − 股票手續費稅」,差的那一塊正好是股票手續費稅。
   這次**不改**這個口徑(改了就要連 Cloud 的 `_stat_legs`、所有統計一起動,而且一般轉帳的手續費
   也會被牽連),改成讓使用者「查得到」:在各報表補一行「手續費與證交稅(投資成本,不計入支出)」。
2. **再投入股利不會重複計算**:`reinvest` 是一筆入投資戶的 income(算收入一次)+ 持股成本增加
   (成本是持股計算,不是另一筆收支)。只要「淨投入」不包含 reinvest,就沒有重複。

## 刻意沒處理 / 已知限制

- **收支與手續費稅口徑沒有改**(手續費稅仍不進支出):這是 App/Cloud 共同且既有的口徑,一般轉帳的手續費也一樣;
  改它會連動所有統計與 Web。這次是補「查得到」。若之後要把手續費稅算成支出,需要同時改 App
  `_rangeTotals`/報表載入器與 Cloud `_stat_legs`/`workspace`,並重新驗證所有報表。
- 日曆格/日標題仍是純收支;只加了圖示(日曆)與標籤(列表),沒有在日標題塞金額。
- CSV 沒有匯出沒有現金流的明細(期初持股/配股/分割)與持股本身;要完整備份請用 App 的備份/同步。
- 桌面小工具、分享海報、AI 查詢沒有補充資訊(口徑一致,只是不顯示)。
- 統計報表套了篩選時不顯示投資補充資訊(避免與篩選範圍矛盾)。
- 年度報告在「整年只有股票買賣、沒有任何收支」時仍走既有的「無資料」分支(`income == 0 && expense == 0` 回 null)。
- 實機視覺未驗證(只跑了單元/Widget 測試與 `flutter analyze`)。

## Web 端應採用的口徑

> 給 Web 首頁/報表同步用。所有金額以**證券幣別**逐幣別累計,顯示時折成帳本本位幣(缺匯率的幣別剔除並提示)。

| 名詞 | 定義 |
|---|---|
| **收入** | 只算 `tx_type = income`(含退款沖銷)。**股利是收入**(分類「股利」:現金股利實收 + 股利再投入成本)。買進/賣出轉帳**不是**收入。 |
| **支出** | 只算 `tx_type = expense`。買進**不是**支出;**手續費與證交稅不算支出**。 |
| **投資買進總額** | 期間內 `stock_trade.trade_type = 'buy'` 的 `amount` 加總(= 股數×價 + 手續費,實際流出交割戶的錢)。 |
| **投資賣出總額** | 期間內 `trade_type = 'sell'` 的 `amount` 加總(= 股數×價 − 手續費 − 證交稅,實際流回交割戶的錢)。 |
| **投資淨投入** | 買進總額 − 賣出總額。**不是收入也不是支出**,報表上要標「未計入收入與支出」。`reinvest`(股利再投入)不計入,`opening`/`stock_dividend`/`split` 沒有現金流也不計入。 |
| **手續費與證交稅** | 期間內 `buy`/`sell` 的 `fee + tax` 加總。視為投資成本,**不計入支出**,在補充資訊裡可查;股利的匯費/預扣稅已從「實收股利」扣掉,不重複算。 |
| **股利收入** | 期間內 `cash_dividend` + `reinvest` 的 `amount`。**已經算在收入裡**,補充資訊只是標示來源,不可再加一次。 |
| **淨資產** | 只含 `include_in_total = true` 的帳戶;投資理財帳戶預設不含。要說明「買進股票會讓淨資產減少(轉帳,不是支出)」並另外顯示「投資市值約 X(不含於淨資產)」;仍計入淨資產的投資帳戶要警示可能與市值重複。 |
| **恆等式(可拿來自我檢查)** | 全部帳戶餘額的變化 = 收入 − 支出 − 股票手續費稅(同幣別、含所有帳戶)。 |

顯示建議(同 App):

- 主行:「投資淨投入 +X」;說明:「買進 A · 賣出 B · 未計入收入與支出」。
- 有手續費稅:「手續費與證交稅 C(投資成本,不計入支出)」。
- 有股利:「股利收入 D(已計入收入)」。
- 期間內沒有任何股票買賣/股利時整塊不顯示;套了篩選的報表也不顯示。
- 交易列表:綁定 `stock_trade.tx_sync_id` 的轉帳顯示「股票買進/股票賣出」,股利再投入顯示「股利再投入」。
