# 「新功能！」公告更新至 3.5.5:合併 3.5 內容 + 補上診斷日誌條目

## 背景

`pubspec.yaml` 在 [2026-09-19-ai-free-chat-query-overhaul.md](2026-09-19-ai-free-chat-query-overhaul.md)
之後的下一個 commit(新增 AI 對話診斷日誌)直接把版本號從 `3.5.0+1` bump 到
`3.5.5+1`,但 `3.5.0` 之間並沒有真的對外發過版——`kWhatsNewContent` 只有
`'3.5.0'` 這個 key(見 [2026-09-18-whats-new-350.md](2026-09-18-whats-new-350.md)),
沒有 `'3.5.5'`。由於彈窗/「我的」頁面入口都是用
`PackageInfo.version`(不含 build number)去對 `kWhatsNewContent` 的 key
(`lib/widgets/ui/whats_new_dialog.dart`),版本號跳到 `3.5.5` 後,原本寫好的
`'3.5.0'` 公告內容就再也不會顯示。

## 內容取捨

1. **Key 從 `'3.5.0'` 改名為 `'3.5.5'`**,原本 7 筆 `WhatsNewItem` 全部保留、
   合併過去——這些功能使用者確實還沒看過公告,不是要捨棄的內容。
2. **精簡描述文字**:原本幾筆(尤其是 AI 對話查詢那筆)描述偏長,合併後 8 筆
   一次列在同一個彈窗裡篇幅會太長,所以在不流失資訊的前提下把每筆描述縮短、
   去掉重複舉例。
3. **新增第 8 筆:AI 對話診斷日誌**(對應
   [4352f137](../../lib/services/ai/free_chat_router.dart) commit「新增ai對話保留log」)。
   這個改動本身只是在 `FreeChatRouter` 的路由/回答流程加了幾行
   `logger.debug(...)`,沒有新頁面、沒有新開關,严格來說偏向工程診斷用途而非
   一般使用者會主動使用的功能。但考量它讓使用者在回報「AI 答錯/答非所問」時
   有地方可以自己先查一次,對受影響的使用者仍是可感知的價值,所以還是收錄
   一筆,但描述誠實地寫成「協助回報問題」而非包裝成獨立大功能。

## 改動檔案

- `lib/whats_new/whats_new_content.dart` — `kWhatsNewContent` 的 `'3.5.0'` key
  改名為 `'3.5.5'`,並新增第 8 筆 `WhatsNewItem`(對應
  `whatsNew355AiChatDebugLogTitle`/`Desc`)。
- `lib/l10n/app_en.arb` / `lib/l10n/app_zh_TW.arb` — 原本的 `whatsNew350*`
  16 個 key 整組改名為 `whatsNew355*`(描述文字同時精簡),並新增
  `whatsNew355AiChatDebugLogTitle`/`Desc` 一組。未動
  `app_zh.arb`/`app_ko.arb`(依[L10n 政策](../../CLAUDE.md))。
- 已跑過 `flutter gen-l10n` 重新產生 `app_localizations*.dart`。

## 入口點

「我的」→「新功能！」,或版本更新/全新安裝後首次啟動 App 自動彈出的公告視窗
(`lib/widgets/ui/whats_new_dialog.dart`)。新增的診斷日誌功能本身的入口點是
「我的」→「關於」→「日誌中心」(`lib/pages/settings/log_center_page.dart`)。
